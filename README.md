# Курсы ЦБ

Symfony 8.1 / PHP 8.5, PostgreSQL, RabbitMQ. Получение курсов и кросс-курсов ЦБ через API и CLI, загрузка истории через
воркеры.

[Архитектура](docs/architecture.md)

## Запуск

Требуется Docker с Compose v2.24+. Для запуска необходмо выполнить команду из каталога проекта:

```sh
docker compose up -d --build --wait --wait-timeout 180
```

Миграции выполняются автоматически при запуске через docker compose. Запускаются один воркер подготовки и два воркера
импорта.

- Swagger UI - http://127.0.0.1:8088/api/doc
- RabbitMQ UI - http://127.0.0.1:15672 (логин и пароль `cbr`)
- PostgreSQL - `127.0.0.1:15432` (база, пользователь и пароль `cbr`)

## Получить курс

```sh
curl -sS 'http://127.0.0.1:8088/api/v1/rates?date=2026-10-22&currency=CAD&base=RUB'
```

Тот же запрос через CLI:

```sh
docker compose exec app php bin/console rates:get --date=2026-10-22 --currency=CAD --base=RUB
```

`date` и `currency` обязательны. Базовая валюта по умолчанию - `RUR`, при обработке нормализуется в `RUB`.

Пример ответа:

```json
{
  "requestedDate": "2026-10-22",
  "effectiveDate": "2026-10-22",
  "previousDate": "2026-10-21",
  "currency": "CAD",
  "base": "RUB",
  "rate": "58.327800000000",
  "previousRate": "58.798300000000",
  "change": "-0.470500000000",
  "changePercent": "-0.80019320"
}
```

| Поле               | Значение                                                        |
|--------------------|-----------------------------------------------------------------|
| `requestedDate`    | Дата из запроса                                                 |
| `effectiveDate`    | Дата начала действия курса пары - может быть раньше запрошенной |
| `previousDate`     | Предыдущая дата котировки, с учетом выходных и праздников       |
| `currency`, `base` | Нормализованные коды запрошенной и базовой валют                |
| `rate`             | Количество единиц `base` за одну единицу `currency`             |
| `previousRate`     | Курс на `previousDate`                                          |
| `change`           | Разница `rate - previousRate` в единицах базовой валюты         |
| `changePercent`    | Изменение относительно предыдущего курса в процентах            |

Расчеты учитывают номинал и используют `BcMath\Number` с округлением half-even. Числа в JSON передаются строками: курс и
разница с 12 знаками после запятой, процент - с 8.

## Загрузить историю

Необходимо выбрать валюты или явно указать все:

```sh
docker compose exec app php bin/console rates:import --currency=USD --currency=EUR
docker compose exec app php bin/console rates:import --all-currencies
```

Повторный импорт пропускает полностью подтвержденные периоды, включая опорный участок перед началом периода. В логах это
событие `cbr.currency_history.skipped`. Для принудительной загрузки из ЦБ и обновления сохраненных котировок:

```sh
docker compose exec app php bin/console rates:import --currency=USD --currency=EUR --force
```

По умолчанию загружаются ровно 180 предыдущих календарных дней без сегодняшнего. `--previous-days=365` задает 365
предыдущих дней: от сегодня минус 365 дней до вчера включительно. Максимум - 3650 дней.

Для загрузки по сегодня необходимо указать точный диапазон через `--from` и `--to`, обе границы включаются. Например, на
23 октября 2026 года:

```sh
docker compose exec app php bin/console rates:import --currency=USD --from=2026-10-01 --to=2026-10-23
```

`--previous-days` и явный диапазон не используются одновременно. Одна опция `--to` без `--from` не допускается.

Команда отправляет задание в `planning`. Воркер подготовки проверяет доступность валют и создает сообщения в `imports`
для загрузки истории каждой валюты. Недоступные для импорта валюты отклоняются без повторов. Успех команды означает
постановку задания, состояние обработки можно проверить так:

```sh
docker compose exec app php bin/console messenger:stats
docker compose logs -f worker-planning worker-import
```

При временных ошибках, включая HTTP 429, выполняются три повтора с задержками примерно 1, 2 и 4 минуты. После этого
сообщение попадает в `failed`. Детали ошибок доступны в логах - `messenger:failed:show` для AMQP не поддерживается.

```sh
docker compose exec app php bin/console messenger:failed:retry --force
docker compose up -d --scale worker-import=3
```

Повторный импорт обновляет данные без дубликатов. Сохранение выполняется через Doctrine ORM в транзакции с повтором при
конфликте уникальности или взаимной блокировке.

## Кеш и очистка

Котировки в PostgreSQL служат кешем. Сущность `CbrHistoryRange` хранит подтвержденные периоды загрузки по ID валюты ЦБ.
Она позволяет отличить выходной без новой котировки от еще не загруженной истории. API и воркеры сохраняют котировки и
подтверждение в одной транзакции - пересекающиеся и соседние диапазоны объединяются.

Если промежуток от действующей котировки до запрошенной даты подтвержден, ответ возвращается из БД без обращения к ЦБ,
включая выходные и праздники. Иначе загружается история за неделю, при необходимости - за 180 дней. Воркер дополнительно
получает опорную котировку перед началом периода. Успешные пустые ответы также подтверждают проверенный период - ошибки
загрузки - нет.

Удалить все котировки, оставив справочник валют:

```sh
docker compose exec app php bin/console rates:clear
```

## Проверки

```sh
docker compose exec app composer check
```

Запускает PHP CS Fixer, PHPStan, проверки конфигурации и схемы Doctrine, PHPUnit.

Источник данных: [XML-интерфейс Банка России](https://www.cbr.ru/development/SXML/)

Полный путь импорта через RabbitMQ с реальными обработчиками и повтором после HTTP 429 или 503 проверяется отдельно:

```sh
docker compose exec -e RABBITMQ_TEST_DSN=amqp://cbr:cbr@rabbitmq:5672/%2f app composer test:broker
```
